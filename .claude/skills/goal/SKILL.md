# /goal — 全部終わらせてから聞くモード

オーナーが `/goal` と言ったら、**今のプロジェクト状態でAIだけで完了できる作業をすべて洗い出し、
質問や進捗確認を挟まずに最後まで実行**する。オーナーの判断・承認が必要な事項は、
作業の途中で都度聞かず、**すべて終わった後にまとめて一度だけ**確認する。

これは `rules.md` Rule 1（重要事項は必ずオーナー確認）を省略するモードではない。
**確認そのものは省略しない。確認の「タイミング」を最後にまとめるだけ**である。

## 1. 対象範囲の洗い出し

1. `らくらく勤怠/specs/TODO_次にやること.md` を読み、未完了タスク（特に🤖印＝AI側の作業）を拾う。
2. 直近の会話・PRの状態（未対応のレビュー指摘、途中の実装など）も対象に含める。
3. 必要に応じて各AI社員のスキルを呼び出し、最新の不足点を洗い出す。
   - `product-scorer`（リョウ）: 完成度スコアと不足リスト
   - `security-auditor`（ハヤト）／`security-guardian`（ノア）: セキュリティの穴
   - `labor-advisor`（ミオ）: 給与・派遣法の論点
   - `legal-advisor`（レン）: 利用規約・プライバシーポリシー等の論点
   - `marketing-writer`（ソラ）／`software-engineer`（カイ）: 実装・資料の不足
4. 洗い出した項目を一つのタスクリストにする（TaskCreate等、この場で使えるタスク管理を使って可視化する）。
   `communications/LOG_004_google_skills_and_moat.md` の「今やれることの棚卸し」と同じ要領で、
   下記3分類に仕分ける。

## 2. 3分類での仕分け

- **A. すぐ着手可**（軽微・自己完結・承認不要）
  → コード修正、ドキュメント・ドラフト作成、レビュー実行、ビルド/テスト確認、既存の掟の範囲内の
    リファクタ等。**このカテゴリだけを、区切りごとに確認を挟まず順番に全部実行する。**
- **B. 要オーナー承認**（rules.md Rule 1：コスト発生・外部公開・方針転換・新機能追加・採用・契約）
  → その場では聞かない。**保留リストに積んで、依存しないAタスクを先に進める。**
- **C. 要オーナーの実操作／外部連携**（Vercel・Supabase・LINEの管理画面操作、支払い、社労士・
  弁護士とのやり取りなど、AIが代行できないもの）
  → AIには実行できないため、**保留リストに積んで最後に一覧で伝える。**

## 3. その場で止めてよい例外（後回しにしない）

以下は「後でまとめて聞く」対象にせず、**その場で止めて確認する**。

- 実行に必須の認証情報・環境変数・パスワード等が無く、技術的にこれ以上進められない場合
- **これからAI自身が実行しようとしている操作が不可逆・破壊的**な場合
  （本番DBへの破壊的操作、force push、秘密情報の外部送信、決済の実行など）
  — 既存の git safety protocol・rules.md の原則をそのまま適用し、実行前に確認する
- 複数の合理的な選択肢があり、選択を誤ると後続のA作業がすべて手戻りになる場合

## 4. 終わったら

1. **完了した作業の一覧**を報告する（何をやったか・結果・変更したファイルやコミット）。
2. **今回AIだけでは完了できなかった/対象外だった項目**とその理由を報告する
   （B・Cに分類したもの、外部の回答待ちのものなど）。
3. **オーナーの判断・承認が必要な事項（B）**を、ここで初めて、まとめて一度に確認する。
   複数あれば `AskUserQuestion` で一括提示するか、箇条書きで一度に尋ねる。
4. **オーナーの実操作が必要な事項（C）**は、質問ではなく「やることリスト」として提示する。
5. 重要な意思決定（AI社員の採用、方針変更等）を行った・提案した場合は、rules.md Rule 3 に従い
   `communications/` にログを残す。

## 掟

- 「聞かずに進める」は思考停止で全部やることではない。B（Rule 1該当事項）の**実行そのものには
  引き続きオーナー承認が必要**——省略するのは「都度聞くタイミング」だけ。
- 破壊的操作・不可逆操作の安全確認は `/goal` モードでも一切省略しない。
- 何が「今できる範囲」かは自己判断に頼らず、TODOと各AI社員の指摘を根拠にする。
- 完了報告は「やったこと」を具体的に（ファイルパス・PR・コミット等）示し、伝聞や推測で済ませない。
